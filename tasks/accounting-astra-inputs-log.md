# Shared input bank

## Canonical additions in app

`app/src/components/ui/inputs/` owns the implementation. Admin receives byte-identical copies and excludes the bank in `.prettierignore`. `verify-input-bank.ts` runs before the accounting suite and checks both parity and the admin boundary.

- Select: search, grouped headings, disabled options, details, search keywords, visible and accessible labels, helper text, required and named form values, compact rows, custom card triggers and trigger children. All popup controls share placement, surface and dialog-safe portal helpers.
- Toggle: visible labels, descriptions and size variants. Checkbox keeps ReactNode labels and descriptions and adds an indeterminate state for the existing data table.
- RadioGroup and Radio: native grouping and keyboard behavior, inline horizontal options, descriptions, disabled options and reduced-motion-aware use of the shared radio animation.
- FileInput, TagsInput and ColorInput: shared anatomy and tokens. The app exercises uploads in its attachment and portal screens, tags in the task form, colors in portal branding, radios in theme settings, and the canonical Select and Toggle at existing call sites.
- TextInput, PasswordInput, Textarea and NumberInput: native accessibility and form metadata, uncontrolled form support and shared size/chrome helpers. NumberInput supports precision and numeric string values while keeping value callbacks. DateInput retains ISO values, bounds and clearability and adds uncontrolled values and read-only behavior.

## Scope and first-pass correction

The initial working tree was uncommitted. This pass resets admin from the app bank, adds shared capabilities in app first and copies them back. HiddenInput is removed: hidden form transport remains native. No color allowlist is needed because both apps use ColorInput.

Feature-owned account card contents, SSN reveal actions, readonly business information and accounting cents parsing stay in their features. All visible field chrome belongs to the canonical bank. Non-field information boxes use the existing glass panel treatment.

## Behavior and conversion notes

- Text, password, textarea, select and numeric callbacks now receive values. Accounting money inputs remain string-valued TextInputs where their feature parses USD into integer cents. Browser verification preserved 0.03; NumberInput stepped 0.03 to 0.04 with a 0.01 step.
- Native FormData metadata, uncontrolled defaultValue, required validation, read-only display fields and input refs remain available. The accounts balance form and tax-link transport keep three native hidden inputs, all explicitly allowed by the gate.
- Files retain native change events, accept/multiple/capture, forwarded refs and reset behavior. App attachments, avatar uploads and portal uploads exercise this API.
- Searchable Select supports grouped account metadata, custom children and compact table triggers. Select restores trigger focus on selection or Escape. Popup portals remain inside their dialog focus scope, using the browser top layer to escape clipping and transformed ancestors.
- DateInput uses the app calendar and its keyboard navigation, min/max bounds and ISO value contract. The former admin-only month/year panels are replaced by the canonical calendar navigation. helperText call sites use description. Read-only and uncontrolled date use cases are supported in the canonical bank.
- Checkbox accepts the Imports wizard's two-line ReactNode label and descriptions. Its native indeterminate state preserves select-all semantics in DataTable; the only DataTable changes are its checkbox import and equivalent accessibility props.
- The SSN reveal action stays in the employee feature as a suffix button; the field surface is TextInput. Read-only expense metadata uses TextInput. Informational cards use the existing glass-card treatment.
- TagsInput preserves multiword text tags, accepts comma-separated values, and supports the admin's email mode. Invalid email drafts retain their text and participate in native form validation. Tag removal and password visibility buttons are keyboard reachable.
- No visible native form controls remain outside the admin bank. No ColorInput exception is needed: app portal branding now uses it. HiddenInput was removed entirely.

## Behavior and conversion notes

- Text, password, textarea, select and numeric callbacks now receive values. Accounting money inputs remain string-valued TextInputs where their feature parses USD into integer cents. Browser verification preserved 0.03; NumberInput stepped 0.03 to 0.04 with a 0.01 step.
- Native FormData metadata, uncontrolled defaultValue, required validation, read-only display fields and input refs remain available. The accounts balance form and tax-link transport keep three native hidden inputs, all explicitly allowed by the gate.
- Files retain native change events, accept/multiple/capture, forwarded refs and reset behavior. App attachments, avatar uploads and portal uploads exercise this API.
- Searchable Select supports grouped account metadata, custom children and compact table triggers. Select restores trigger focus on selection or Escape. Popup portals remain inside their dialog focus scope, using the browser top layer to escape clipping and transformed ancestors.
- DateInput uses the app calendar and its keyboard navigation, min/max bounds and ISO value contract. The former admin-only month/year panels are replaced by the canonical calendar navigation. helperText call sites use description. Read-only and uncontrolled date use cases are supported in the canonical bank.
- Checkbox accepts the Imports wizard's two-line ReactNode label and descriptions. Its native indeterminate state preserves select-all semantics in DataTable; the only DataTable changes are its checkbox import and equivalent accessibility props.
- The SSN reveal action stays in the employee feature as a suffix button; the field surface is TextInput. Read-only expense metadata uses TextInput. Informational cards use the existing glass-card treatment.
- TagsInput preserves multiword text tags, accepts comma-separated values, and supports the admin's email mode. Invalid email drafts retain their text and participate in native form validation. Tag removal and password visibility buttons are keyboard reachable.
